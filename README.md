# NFC Tool — Android NFC Reader & Writer

A native Kotlin/Jetpack Compose NFC diagnostic utility. It reads and writes only data exposed through Android's public NFC APIs and deliberately does **not** authenticate, guess keys/passwords, bypass access controls, or access payment, identity, transit, secure-element, or other protected credentials.

## Open, build, and install

1. Open `android-nfc-tool` in Android Studio (JDK 17 / Android Studio Ladybug or newer).
2. Let Gradle sync, then run the `app` configuration, or run `./gradlew assembleDebug` from this directory once a Gradle wrapper is generated by Android Studio.
3. Connect an Android 8.0+ phone with Developer options / USB debugging enabled and select it as the deployment device.
4. Enable NFC in Android Settings. The app has only the `android.permission.NFC` permission; no network, storage, location, camera, microphone, contacts, or account permissions are requested.

## What it supports

- Foreground Reader Mode scanning for NFC-A, NFC-B, NFC-F, NFC-V, and barcode tags.
- Android-exposed NDEF parsing: text, URI, MIME, Smart Poster indication, external type, and raw/unsupported records.
- Safe NDEF writes to writable `Ndef` tags and formatting of `NdefFormatable` tags, after capacity/writable validation and explicit confirmation.
- Diagnostics for exposed `NfcA`, `NfcB`, `NfcF`, `NfcV`, `IsoDep`, `MifareClassic`, `MifareUltralight`, `Ndef`, and `NdefFormatable` technology objects.
- Metadata-only local scan history. Payload persistence is disabled by default and intentionally not implemented in this first production-safe release.

## Android limitations and protection reporting

Android does not offer a universal raw-memory or security-status API. This app reports only observations it can substantiate:

- NDEF writable/read-only reflects `Ndef.isWritable()` for the exposed NDEF area—not a claim about all physical memory or a lock mechanism.
- A missing/failed NDEF interface is reported as unsupported or partially accessible. It is **not** reported as “no data,” “encrypted,” or “password protected.”
- UID, ATQA, SAK, ATS-like historical bytes, and technology properties are marked unavailable when Android does not expose them.
- MIFARE technology visibility varies by phone hardware. The app lists exposed metadata only and never attempts sector authentication.
- ISO-DEP presence does not authorize APDU probing of protected credentials. The app does not send arbitrary commands.

## Testing with ordinary tags

Use blank/writable NDEF Type 2/Type 4 development tags or tags you own. Test an empty tag, text and URI records, multiple records written by another NDEF app, read-only NDEF tags, unsupported tags, and removing a tag mid-operation. Do not use bank, payment, transit, government ID, or access-control cards.

Unit tests cover NDEF text/URI decoding and raw hexadecimal validation. Device tests should additionally cover NFC-disabled hardware, tag loss, capacity limits, malformed messages, multi-technology tags, ISO-DEP, and hardware-exposed MIFARE variants.
